### Анализ и проектирование на UML
Полный цикл проектирования информационной системы. Реализованы все 7 лабораторных работ, включающие:
* **Функциональное моделирование:** Диаграммы использования (Use Case) и деятельности (Activity).
* **Статическое описание системы:** Концептуальные и технические диаграммы классов (Class Diagram), спроектированные с учетом многослойной архитектуры.
* **Динамическое моделирование:** Диаграммы последовательности (Sequence) и состояний (State Machine) для описания логики взаимодействия объектов.
* **Физическая архитектура:** Модели развертывания (Deployment Diagram) с описанием узлов и артефактов системы.

### Курсовой проект
В рамках курсового проекта была разработана веб-платформа конного клуба **Dust & Glory**, объединяющая пользовательский интерфейс и серверную часть в единую систему. Проект реализован как full-stack приложение: frontend отвечает за пользовательский интерфейс и навигацию, а backend обеспечивает обработку данных, авторизацию, работу с базой данных и API.

1. Используемый стек

- **Backend:** NestJS, TypeScript, Prisma, PostgreSQL
- **Frontend:** HTML, CSS, JavaScript, Handlebars
- **API:** REST API, GraphQL
- **Авторизация:** JWT, cookies, роли пользователей
- **Интеграции:** Swagger, SSE, S3-совместимое хранилище, деплой на Render
- **Инструменты:** Git, Prisma Migrate, Swagger UI, GraphQL Playground

2. Основные реализованные задачи

- разработка многостраничного сайта с адаптивной версткой;
- проектирование предметной области и структуры базы данных;
- реализация CRUD-операций для сущностей клуба;
- настройка REST API и GraphQL-схемы;
- добавление механизма аутентификации и разграничения прав доступа;
- реализация серверных событий (SSE) для обновления данных в реальном времени;
- настройка кэширования, валидации данных и обработки ошибок;
- подключение документации API и деплой приложения.

### Управление требованиями (УТ)
Документирование и формализация спецификаций программного продукта. 
* **Выполненные этапы:** Сбор и классификация требований, верификация по критериям качества (атомарность, выполнимость, тестируемость), приоритизация методами MOSCOW/RICE и формирование матрицы трассировки (RTM).
* **Текущий статус:** Разработка завершающих этапов — регламентация процесса управления изменениями (ЛР 4) и подготовка итоговой спецификации SRS по стандарту IEEE 830 (ЛР 5).
